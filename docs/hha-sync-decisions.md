# HHAeXchange sync decisions

What the HHAeXchange (HHA) sync decides on its own, what it hands to an admin, and what is still open.
The admin **HHA Sync** page shows every run, every change, the section 2 exceptions, the people who share an
email and the patients with more than one coordinator.

- **Source of truth:** HHA. The sync is one-way; PreventaTri never writes back to HHA.
- **Where the rules live:** `constants/hhaExchangeConstants.js` (managed fields, exception codes,
  run order) and the runners in `services/hha*SyncServices.js`.
- **Where a run reports:** three tables, all admin-only, none in the Activity Log.
  - `hha_sync_runs`: one row per run (trigger, who pressed Sync, start/end, status, per-resource counters).
  - `hha_sync_changes`: one row per record a run created or changed, with `{field, from, to}` per field,
    patient fields included (decided 2026-10-02; admin-only). Rows from before that date hold patient
    personal fields as `{field, redacted: true}` with no values.
  - `hha_sync_exceptions`: the section 2 worklist (below).
- **Logs:** counters only. Exception records never go to CloudWatch, because their details carry HHA data.

## 1. Resolved: rules the sync applies automatically

### Run and identity

| Decision                                        | Rule                                                                                                                                                                               |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Run order                                       | Case managers, then nurses, then caregivers, then patients, then visits. People exist before patients link to them.                                                                |
| One run at a time                               | A Redis lock blocks a second run while one is in progress, across every server.                                                                                                    |
| When records are rewritten                      | Only when HHA's owned fields change (a hash of those fields). Links, derived county/region and email are checked on every run, because they depend on PreventaTri data too.        |
| Nurse or caregiver                              | HHA lists nurses inside the caregiver feed. The `GetNurses` roster decides who is a nurse. Without the roster the caregiver import stops, rather than import nurses as caregivers. |
| A nurse imported as a caregiver by an older run | Converted in place into a nurse (same login and id), and the caregiver row removed. Reported as `CAREGIVER_RECLASSIFIED_AS_NURSE`.                                                 |
| New people                                      | Created unverified, with no invitation email. An admin reviews and invites them. Nobody is linked to a patient before they accept (see Patient links).                             |
| A failed lookup                                 | Never read as "nothing there". The current value is kept and the run reports `LINK_LOOKUP_FAILED` or `UPSERT_FAILED`.                                                              |

### Who owns which field

| Record       | HHA owns (read-only in PreventaTri)                                                                                                                                                                             | PreventaTri owns (editable)                                                                                                                                                                         |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Patient      | Name, birth date, gender, status, address, phones, emergency contact, Medicaid ID, **primary nurse while HHA names one**, **the coordinators a case manager is chosen from**, **county while the ZIP resolves** | Email, risk level, diagnoses, notes, **secondary nurse**, **primary nurse when HHA names none**, **primary nurse and case manager while HHA's is not active**, county when the ZIP does not resolve |
| Nurse        | Name, phone, address, role, status, licence number, NPI, **primary region while the ZIP resolves**, email (see below)                                                                                           | Licence state and expiry, **secondary regions**, on-call, contact method, joining date, notes, primary region when the ZIP does not resolve                                                         |
| Caregiver    | Name, phone, address, role, status, language, hire and termination dates, email (see below)                                                                                                                     | Relationship, contact method, on-call, notes, patient assignments                                                                                                                                   |
| Case manager | Name, status, email (see below)                                                                                                                                                                                 | Title, phone, regions, **manually assigned patients**, contact method, language, start date, notes                                                                                                  |

The API refuses an edit to an HHA-owned field with `400 HHA_MANAGED_FIELD_READ_ONLY`; the forms show those fields greyed out.

### Email

| Situation                                              | Rule                                                                                                                                                                                                                                                                                  |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| HHA has no email at import                             | A placeholder `…@hhax.invalid` address is created. An admin may replace it while it is still the placeholder.                                                                                                                                                                         |
| HHA's email changes later                              | The login email follows HHA on the next run (caregivers, nurses, case managers), unless an admin typed the login email.                                                                                                                                                               |
| HHA has no email, PreventaTri has one                  | Kept (the placeholder, or the address an admin typed in).                                                                                                                                                                                                                             |
| HHA's email already belongs to someone at import       | The person is **not imported**: `DUPLICATE_EMAIL` (decided 2026-10-05). They wait in `hha_pending_imports` until an admin gives them a unique email on the **Shared emails** view; the next sync then imports them with it. An unclaimed profile of the same role is adopted instead. |
| HHA's new email belongs to someone else, or is invalid | The current email is kept: `EMAIL_IN_USE` / `INVALID_EMAIL`.                                                                                                                                                                                                                          |
| An admin types a login email                           | Allowed while the login is the placeholder or HHA's address is shared. Every later run keeps it, even if HHA's email changes (decided 2026-10-05).                                                                                                                                    |
| HHA's own address                                      | Stored beside the login email (`users.hha_email`), so the **Shared emails** view can list everyone HHA gives one address.                                                                                                                                                             |

### Patient links

A nurse or case manager is linked to a patient only while **active**: profile status Active, not archived, and
invitation accepted (decided 2026-10-09). Escalations and manual nurse assignment already held people to the same bar.

| Situation                                             | Rule                                                                                                                                                                                                                       |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| HHA names someone who is not active                   | Not linked. The patient waits for them (`patients.hha_pending_*_profile_id`) and keeps whoever it has. The person is reported once, not once per patient: `*_INVITATION_PENDING` or `*_NOT_ACTIVE`.                        |
| While a patient waits                                 | The primary nurse and the case manager can be edited on the patient (Care Team). The case manager may be any active case manager, not only an HHA coordinator.                                                             |
| First coordinator not active, a later one is          | The next active coordinator in HHA's order stands in, unless an admin's pick is on the patient.                                                                                                                            |
| The person becomes active, slot empty or sync-made    | Linked at once: when they accept (also by a password reset or email verification), or in the last step of a running sync. The person's exception closes with a note saying how many patients they got.                     |
| The person becomes active, someone was chosen instead | An admin's pick, or the coordinator that stood in, stays. The next sync raises `PRIMARY_NURSE_CONFLICT` / `CASE_MANAGER_CONFLICT` and the admin chooses. Keeping the current one stays quiet until HHA names someone else. |
| A linked person stops being active                    | The next sync removes the links it made and reports the person as `*_NOT_ACTIVE`. Active again: the links come back. A link an admin made is left alone.                                                                   |

| Situation                                         | Rule                                                                                                                                                                                                |
| ------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Coordinators                                      | Every coordinator HHA lists (up to three) is stored on the patient, in HHA's order. They are shown on the Care Team card and the **Coordinators** view.                                             |
| Case manager                                      | One coordinator is the patient's single case manager: the one an admin chose, otherwise HHA's **first**. The others have no access, escalations or assignments here.                                |
| The chosen coordinator leaves the patient in HHA  | The choice is cleared and the first coordinator is used again: `SELECTED_COORDINATOR_REMOVED`.                                                                                                      |
| Coordinator named, one match                      | Linked. Names are matched without case or extra spaces.                                                                                                                                             |
| Two case managers share the name                  | The coordinator ids are read from `GetPatientDemographics` (one call per patient) and matched by id.                                                                                                |
| Primary nurse                                     | HHA's `NurseID` while HHA names a nurse imported here; the field is then locked, even outside the nurse's regions.                                                                                  |
| HHA names no nurse, or one not imported here      | The field unlocks and an admin may pick the primary nurse (region rules apply). The sync keeps that pick. A nurse HHA had set is cleared only when HHA now names nobody (decided 2026-10-06).       |
| HHA later names a nurse, the admin picked another | The admin's pick stays and `PRIMARY_NURSE_CONFLICT` is raised. The admin chooses on the Exceptions tab: the HHA nurse (locks again) or the PreventaTri nurse (quiet until HHA names another nurse). |
| Secondary nurse                                   | Admin's choice. The sync clears it only when it now equals the primary nurse (the database forbids that), or when the sync moved the patient to a county the secondary nurse does not cover.        |
| County                                            | Derived from the ZIP (any US state). While it resolves, HHA's county wins and is locked.                                                                                                            |
| Nurse primary region                              | Derived from the nurse's ZIP the same way, and locked while it resolves. Secondary regions are never touched.                                                                                       |
| A nurse's regions change                          | Manual patients the nurse no longer covers lose that nurse; an HHA patient keeps a primary nurse HHA assigned, but loses one an admin picked.                                                       |

### Case manager patient lists

- Saving a case manager's patient list only changes its **manual** patients; HHA-linked patients stay.
- An HHA patient's case manager is picked on the patient, and only while it waits for HHA's case manager or holds an admin's pick.
- The patient picker never offers HHA patients.
- Adding another case manager's HHA patient is refused (`400 HHA_MANAGED_FIELD_READ_ONLY`).
- Changing a case manager's regions never touches its patients.

### Visibility

A nurse sees the patients in their regions **plus** every patient they are the primary or secondary nurse of,
in the patient list and detail, alerts, submissions and the nurse dashboard.

### Archive

| Record archived in PreventaTri | What the sync does next                                                                                                     |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| Any                            | Updates it in place and never un-archives it. There is no restore.                                                          |
| Patient                        | Updates demographics and county; never changes its links. (Archiving already removed its case manager and caregiver links.) |
| Nurse                          | Updates the nurse. Patients the sync gave them lose that link; the nurse is reported as `NURSE_NOT_ACTIVE`.                 |
| Caregiver                      | Updates the caregiver.                                                                                                      |
| Case manager                   | Patients the sync gave them lose that link; the case manager is reported as `CASE_MANAGER_NOT_ACTIVE`.                      |

A record deleted or discharged in HHA is never archived in PreventaTri; only its status changes.

## 2. Needs admin approval: what the sync reports instead of guessing

Each row is an item on the HHA Sync page's Exceptions tab. **Fix in** says where the correction belongs.

How an exception lives:

| Event                                                 | Result                                                                                                                                                                                                                                                                                              |
| ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| First reported                                        | One row, **Open**. Every exception is stored; there is no cap.                                                                                                                                                                                                                                      |
| Reported again by a later run                         | Same row: `occurrences` goes up. A **Resolved** row reopens; a **Dismissed** row stays dismissed.                                                                                                                                                                                                   |
| A clean run reads the record and no longer reports it | **Resolved by sync**. Only after the resource finished cleanly, and only for a record that run read (the visit feed covers 30 days, so an unread visit proves nothing). The `ARCHIVED_*_UPDATED` codes never close on their own: they fire only when the record changes, so they wait for an admin. |
| Admin                                                 | **Resolve** or **Dismiss** with a note, or **Reopen**. Who and when are stored. A reopen, by an admin or by a repeat, keeps who last closed the row and the note.                                                                                                                                   |
| `DUPLICATE_EMAIL` / `EMAIL_IN_USE`                    | Also store the shared address and the PreventaTri user who already holds it, so the page can open them. They close on their own once an admin gives the person a unique email.                                                                                                                      |
| `*_INVITATION_PENDING` / `*_NOT_ACTIVE`               | One row per person, with no record: the row names the nurse or case manager, shows how many patients wait for them and lists those patients. Closed with a note when the person becomes active, or by the sync once no patient waits for them.                                                      |
